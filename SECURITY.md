# Security policy

## Supported versions

Security fixes are made against the latest released version and the default
development branch.

## Reporting a vulnerability

Please do not open a public issue for a suspected vulnerability. Use GitHub's
private vulnerability reporting for this repository, once it is enabled in the
repository settings. Include a clear reproduction, impact assessment, and any
relevant redacted logs.

If private reporting has not yet been enabled, contact the repository owner
through a private GitHub channel and avoid sharing credentials, access tokens,
or account details.

This project deliberately avoids reading or copying provider credential files.
Reports involving process control, temporary files, Unix-socket access, PATH
interception, or unintended command replay are especially useful.
